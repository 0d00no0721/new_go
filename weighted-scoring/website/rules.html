规则详解

加权点目围棋 完整规则（参考 加权点目围棋规则.md）

快速理解

在标准 19 路围棋上，用位置权重表替代"每点 1 目"：每个棋子和每个独占空点都按其位置权重 W 计值。中央等"低效区"权重高、角部等"高效区"权重低，使各区加权占领价值趋同，逆转"金角银边草肚皮"，让"下天元"值得考虑。

1 权重表

位置W说明
星位 D160.74角部高效，权重低
天元 K101.72中央低效，权重高（逆转金角银边）
一线 A190.76一线适度低（不鼓励但不禁止）
三线边 K171.13边中适度补偿
  • 格式：19×19 row-major 浮点表，第 1 行 = 顶部，第 1 列 = 最左侧。
  • 范围：W ∈ [0.53, 2.76]；ΣW = 421.59（标准 19 路 Σ=361）。
  • ΣW > 361 是设计结果：权重是"价值调节器"，中央被赋 >1 补偿其低占领价值，角部 <1 压低其高效价值，无需归一化。

2 数子公式（加权 area scoring）

步骤说明
移除死子死子不计入任何一方，其位置变空点参与地域 BFS
子分每个活子按其位置权重 W 计入其颜色
空分（BFS）空连通块按邻接棋色判定归属：只邻黑→黑独占空（每点按 W 记黑）、只邻白→白独占空、邻黑白或都不邻→中性不计
加权总分black_weighted = Σ(黑活子 W) + Σ(黑独占空 W)；white 同理

black_weighted = Σ(黑活子位置 W) + Σ(黑独占空位置 W)

white_weighted = Σ(白活子位置 W) + Σ(白独占空位置 W)

3 贴目与胜负判定

采用改造版 KataGo final_score 的约定（difference-komi）：

finalWhiteMinusBlack = white_weighted − black_weighted + komi

> 0 → 白胜（W+X.X）；< 0 → 黑胜（B+X.X）；== 0 → 和局（0）

结果串 1 位小数，与引擎 final_score 完全对齐。默认贴目 ENGINE 采用 7.5（标准中国贴目；3 轮标定数据不可信，见收敛报告_komi_utility校准.md §2），app 中可调整。

4 回归保证：W=1 ≡ 标准数子

当权重表全为 1.0 时：

  • black_weighted = 黑活子数 + 黑独占空数 = 黑 area；white 同理。
  • finalWhiteMinusBlack = white_area − black_area + komi = 标准中国数子。
  • 即加权规则退化为标准 area scoring，并与引擎 final_score（W=1）逐位对照一致。

5 死子处理

死子由调用方显式传入（GUI 经引擎终局判定或用户手标）。死子移除后其位置变空点参与地域 BFS：若该空点只邻某色，归该色独占空。与引擎 final_score（Tromp-Taylor 不移除死子）对齐时传空死子集。

6 "逆转金角银边"机制

区域加权贡献vs 星位
corner34（星位基准）0.50100%
center（中央）0.55+10%
edge34（边中）0.47−6%
low12（一二线）0.52+4%

机制：中央位置 W 高（如天元 1.72，占领即得高分），角部 W 低（如星位 0.74，占领得分被压低）。AI 在搜索阶段因 scoreMean += Σ(W−1)×ownership 而响应权重，从而增加中央下法。

7 实现接口

数子逻辑由 scoring.py（Python，GUI/CLI 共用）与 scoring.js（JS，官网热力图）双端口实现，1:1 对应：

# Python
from scoring import score_game, load_weights
weights = load_weights("weight_table_final.txt")     # 2D list 19×19
res = score_game(stones, weights, komi=7.5)         # res["black_weighted"], res["result"] ...
// JavaScript（官网）
import { parseWeightTable, scoreGame } from "./js/scoring.js";
const weights = parseWeightTable(WEIGHT_TABLE_TEXT);
const res = scoreGame(stonesMap, weights, 7.5, deadSet);
