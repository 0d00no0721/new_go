# 加权点目围棋规则

> 方向：`new_go/weighted-scoring/`
> 实现：`scoring.py`（纯 Python，GUI/CLI/web 共用）/ `scoring.js`（FE-WEB 端口，1:1 对应）
> 关联：`收敛报告.md`（权重表迭代过程与最终结果）、`weight_table_final.txt`（最终权重表）

---

## 1 一句话

用**位置权重表**替代标准数子中"每点 1 目"的假设：每个棋子和每个独占空点都按其位置的权重 W 计值，使中央、边、角各位置的**加权占领价值趋同**，从而逆转"金角银边草肚皮"，让"下天元"值得考虑。

## 2 权重表

- **格式**：19×19，row-major，空格分隔浮点，文件第 1 行 = 棋盘顶行，第 1 列 = 最左列。
- **坐标系**：与 `ban-selection/scoring.py` 一致，`stones` / `dead_stones` 用 1-based `(row, col)`，`row=1` 顶、`col=1` 左。
- **加载**：`scoring.load_weights(path)` → 2D list（0-indexed `[r][c]`，`r=0` 顶）。
- **最终表关键值**（`weight_table_final.txt`，见 `收敛报告.md` §4）：

| 位置 | W | 说明 |
|------|---|------|
| 星位 D16 | 0.74 | 角部高效，权重低 |
| 天元 K10 | 1.72 | 中央低效，权重高（逆转金角银边）|
| 一线 A19 | 0.76 | 一线适度低（不鼓励但不禁止）|
| 三线边 K17 | 1.13 | 边中适度补偿 |

- **范围**：W ∈ [0.53, 2.76]；**ΣW = 421.59**（标准 19 路 Σ=361）。

### 2.1 ΣW = 421.59 的含义

标准 19 路每点权重 1.0，总权重 361（=棋盘点数）。最终表 ΣW = 421.59 > 361，是因为中央等"低效区"被赋了高于 1 的权重以补偿其低占领价值，而角部等"高效区"权重低于 1。**这不是一个 bug**，而是设计的直接结果：权重表不是概率分布，而是"价值调节器"，其总和无需归一化到 361。

> 推论：加权对局的"总分"普遍大于 361，因此**贴目需要与 ΣW 匹配地重新校准**才公平。当前实现沿用引擎默认 komi=7.5（见 §4），是否随 ΣW 缩放是开放的研究问题，不在本规则文件定型范围内。

## 3 数子公式（加权 area scoring）

终局盘面由 `stones`（活子）+ `dead_stones`（死子）+ 空点组成。计算步骤：

1. **移除死子**：`dead_stones` 中的点不计入任何一方，其位置变为空点参与地域 BFS。
2. **子分**：每个活子按其位置权重 W 计入其颜色。
3. **空分（BFS 数空）**：空连通块（4-邻接）按其邻接的棋色判定归属：
   - 只邻黑 → **黑独占空**，块内每点按其 W 计入黑；
   - 只邻白 → **白独占空**，块内每点按其 W 计入白；
   - 邻黑白双方或都不邻 → **中性（dame）**，不计入任一方。
4. **加权总分**：

   ```
   black_weighted = Σ(黑活子位置 W) + Σ(黑独占空位置 W)
   white_weighted = Σ(白活子位置 W) + Σ(白独占空位置 W)
   ```

BFS 数空结构移植自 `ban-selection/scoring.py`（无禁点版本）；加权累加是本方向的新增。

## 4 贴目与胜负判定

采用**改造版 KataGo `final_score` 的约定（difference-komi）**，而非 `ban-selection` 的 `half+komi`：

```
finalWhiteMinusBlack = white_weighted - black_weighted + komi
```

- `finalWhiteMinusBlack > 0` → 白胜，`result = "W+{值:.1f}"`，`winner = "W"`；
- `finalWhiteMinusBlack < 0` → 黑胜，`result = "B+{-值:.1f}"`，`winner = "B"`；
- `== 0` → 和局，`result = "0"`，`winner = ""`。

**结果串格式与引擎对齐**：1 位小数（引擎 `%.1f`），如 `B+163.5`、`W+7.5`、`0`。

### 4.1 为什么不用 ban-selection 的 half+komi

`ban-selection` 用"基准 ± komi"门槛（黑需 > half+komi），其 komi 4.25 ≈ 中国规则"贴子"半值。本方向的数子由**改造版 KataGo 引擎**直接产出 `final_score`，引擎内部用的是 `white_minus_black + komi`（见 `katago-src/cpp/game/boardhistory.cpp:700`：`setFinalScoreAndWinner(boardScore + ... + rules.komi)`，`boardScore = white_weighted − black_weighted`）。为保证 `scoring.py` ↔ 引擎 `final_score` 一致，**必须沿用引擎的 difference-komi 约定**。

### 4.2 komi 取值

- 默认 `komi = 7.5`（引擎默认、`play_game.py` 默认）。
- `komi` 是 `score_game(...)` 的入参，可任意指定（如研究 0 贴目时传 0）。
- 见 §2.1：是否随 ΣW 缩放 komi 是开放问题。
- **标定数据不可信，采用标准值**：3 轮 komi 标定均未自然双 pass 终局，`final_score` 走 NN 估算而非真实加权数子，故不采用任何标定值，改用标准中国贴目 7.5。详见 `收敛报告_komi_utility校准.md` §2。

## 5 回归保证：W=1 ≡ 标准 area scoring

当权重表全为 1.0（`W≡1`）时：

- `black_weighted = 黑活子数 + 黑独占空数 = 黑 area`；
- `white_weighted = 白活子数 + 白独占空数 = 白 area`；
- `finalWhiteMinusBlack = white_area − black_area + komi` = 标准中国数子。

即**加权规则退化为标准 area scoring**。`test_scoring.py` 以此为回归基线，并与引擎 `final_score`（W=1、Tromp-Taylor 规则 + 双 pass 的确定性硬数子）逐位对照一致。

## 6 死子处理

- `dead_stones` 由调用方显式传入（GUI 经引擎 `final_status_list dead` 获取，或用户手标）。
- 死子移除后其位置变空点，参与地域 BFS：若该空点只邻某色，归该色独占空（死子的"地"被对方接收）。
- **与引擎对齐**：引擎 `final_score` 在 Tromp-Taylor 规则下不移除死子（所有子都计），与 `scoring.py` 传 `dead_stones=∅` 等价；含死子的对局需调用方先取得引擎 `final_status_list dead` 再传入，以保证双方数子逻辑一致。

## 7 "逆转金角银边"机制

标准围棋（W=1）中，角部因"两条边做墙"效率最高，中央最低（"金角银边草肚皮"）。迭代收敛后的权重表（`收敛报告.md` §3-4）使各区**加权贡献**趋同星位 ±15%：

| 区域 | 加权贡献 | vs 星位 |
|------|---------|---------|
| corner34（星位基准）| 0.50 | 100% |
| center（中央）| 0.55 | +10% |
| edge34（边中）| 0.47 | −6% |
| low12（一二线）| 0.52 | +4% |

机制：中央位置 W 高（如天元 1.72），占领即得高分；角部 W 低（如星位 0.74），占领得分被压低。AI 在搜索阶段因 `scoreMean += Σ(W−1)×ownership`（`searchresults.cpp:486`）而响应权重，从而增加中央下法——"下天元"从低效变为值得考虑。

## 8 接口

### 8.1 Python（`scoring.py`）

```python
from scoring import score_game, load_weights

weights = load_weights("weight_table_final.txt")          # 2D list 19×19
res = score_game(
    stones,            # dict[(row,col)] -> "B"/"W"，1-based
    weights,           # 2D list / dict / flat row-major
    komi=7.5,
    dead_stones=None,  # set[(row,col)]，默认空
    rows=19, cols=19,
)
# res["black_weighted"], res["white_weighted"], res["result"], res["winner"], res["detail"]
```

### 8.2 JavaScript（`scoring.js`，FE-WEB）

```js
import { parseWeightTable, scoreGame } from "./scoring.js";
const weights = parseWeightTable(text);                   // 19×19 文本 → 2D 数组
const res = scoreGame(stonesMap, weights, 7.5, deadSet);  // stones: Map<"r,c","B"|"W">
// res.black_weighted, res.white_weighted, res.result, res.winner, res.detail
```

`scoring.js` 与 `scoring.py` 1:1 对应（Python `dict`/`set` ↔ JS `Map`/`Set`，键 `"r,c"`），同一盘面应给出完全相同的结果。
